1. Executive Summary

A Kotlin/Jetpack Compose Android ERP client built on a clean MVVM + Repository architecture with a single :app module. The project is internally consistent: one HTTP client, one session owner, one navigation graph, and no local business database. The findings are predominantly dead abstractions and hardening gaps rather than structural problems.

10. Authentication

Traced end to end: pairing gate → login → Keystore storage → request injection → sliding refresh → 401 handling → revocation → logout. A single auth system exists — no duplicate token manager, no mock auth, no debug bypass, no hardcoded credentials.

  1. Pairing gate — VectisNavGraph.kt:56-62: not paired → Pairing; paired but no session → Login; else Dashboard.
  2. Pairing — via QR scan (CameraX + ML Kit) or manual code; stores device id + device token.
  3. Login — AuthRepositoryImpl.login() persists token, user id, role, name, and uppercased preferred currency on success (AuthRepositoryImpl.kt:28-37).
  4. Storage — EncryptedSharedPreferences (AES256_SIV keys / AES256_GCM values) on an AES256_GCM MasterKey, with an in-memory cache. Fallback: degrades to plaintext SharedPreferences on Keystore failure (SecureStorage.kt:170-174).
  5. Injection — AuthInterceptor adds the Bearer header; DeviceInterceptor adds device headers; an OkHttp authenticator retries once with the token on an unauthenticated 401.
  6. Sliding refresh — server X-New-Token replaces the stored token (AuthInterceptor.kt:29-32); getMe() runs every 15 minutes.
  7. 401 — error body mapped to a user-facing reason, session cleared, navigation reset.
  8. Revocation — a 401 with X-Device-Revoked: true clears pairing + session and routes to Pairing.
  9. Logout — server call is best effort, but local credentials are always wiped in a finally block, so a network failure cannot leave a stale local session.

Token store silently degrades to plaintext

Evidence
SecureStorage.kt:170-174 — any Keystore exception falls back to unencrypted getSharedPreferences
Why it matters
Session JWT, device token, user id, role and name then sit in a readable plaintext XML file, and the failure is swallowed with no log and no user-facing warning
Recommendation
Log loudly, warn in Settings, and consider refusing to persist the auth token when the Keystore is unavailable

12. Security Findings

Secrets are redacted per the audit rules.

HIGH  Cleartext HTTP permitted application-wide

Evidence
AndroidManifest.xml:24 usesCleartextTraffic="true"; SecureStorage.kt:151 default http://10.0.2.2:3000
Impact
Session JWT, device token, and login credentials can be sent over plaintext HTTP to any server URL a user types. A network attacker can capture and replay them
Recommendation
Remove the attribute; add a network security config scoping cleartext to emulator/localhost only; enforce https:// in the URL field

MEDIUM  Keystore → plaintext storage fallback, silently

Evidence
SecureStorage.kt:170-174
Impact
All session and device credentials become readable to anything with app data access, with no signal that security degraded
Recommendation
Log the failure, surface it in Settings, and avoid persisting the auth token when the Keystore is unavailable

MEDIUM  401 response bodies written to logcat

Evidence
AuthInterceptor.kt:49-56 — peekBody(2048).string() logged with Log.e alongside method and full URL
Impact
Server error bodies may carry session and account detail; logcat is readable by other apps on older targets and by anyone with adb
Recommendation
Log status code and the mapped user reason only

LOW  Debug APK and build outputs in the project directory

Evidence
app-debug.apk at the repository root, alongside build/, .gradle/, .idea/, .kotlin/
Impact
Risk of shipping a debug-signed, unminified build
Recommendation
Verify .gitignore covers *.apk, build/, .idea/

LOW  No certificate pinning; release not minified

Evidence
No network_security_config.xml or CertificatePinner; isMinifyEnabled = false
Recommendation
Defense-in-depth — enable R8 for release; pin only if the threat model warrants it

Informational

  • POST_NOTIFICATIONS declared but unused.
  • Default system launcher icon in use.
  • Searched for and not found: committed API keys, hardcoded bearer tokens, BuildConfig.DEBUG branches, TODO/FIXME/HACK markers, disabled certificate validation, or WebView configuration.
